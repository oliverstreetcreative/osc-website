# lib/scripts — the script store's code (client-website matter, SPEC §14) 🤖

Created by the client-website worker, 10/3/26, for **Scripts**: the client's front door for scripting ("knock off
Google Docs"), live co-editing with suggestions, one source the portal, the hub, the prompter and every export read.

**What the machine was thinking:** the editor (browser), the server render (hub, prompter, PDF) and every export must
agree on what a script says and how long it runs, so the logic they share lives here once. The suggestion library is
used only to TRACK edits; accepting/rejecting, authorship and the server's guard are ours, because reading the
installed code and fuzzing it found gaps (SPEC §14 "v5: build findings").

- `schema.ts` the document (AV rows) · `doc.ts` import, views, THE render · `suggestions.ts` the editor's list
- `timing.ts` words ÷ pace, THE implementation (nothing else re-implements timing); `timing.vectors.json` is
  GENERATED by `python3 scripts/test_script_timing.py --vectors` from the reference `scripts/script_timing.py`
  (hand-checked lines + the real Harmon and Gex rows): never hand-edit
- `marks.ts` suggestion ids, the `sm` mirror for node marks · `resolve.ts` accept/reject · `normalize.ts` suggest mode
- `guard.ts` the server's suggester check
- `server/` access, the live registry, the importer (server only) · `client/` the browser's sync + TipTap extensions
- Tests: `node --conditions=import --import tsx --test lib/scripts/*.test.ts` (the suggestion library is ESM-only);
  `timing.test.mjs` with plain `node --test`. `fuzzkit.ts` is shared test scaffolding, not app code.

Rules: no regex lookbehind anywhere a browser runs it (older iPhones). `timing.ts` stays erasable TypeScript with no
`@/` imports (plain Node strips its types for `timing.test.mjs`). New tests read real scripts from Dropbox at test
time and skip without it; no new client text in the repo (`timing.vectors.json` already carries the real-script rows
it was generated from). Change a rule in `resolve.ts` / `normalize.ts` / `guard.ts` only with the property tests
passing. Live status: the matter's HANDOFF (`Matters/client-website/HANDOFF.md`).
